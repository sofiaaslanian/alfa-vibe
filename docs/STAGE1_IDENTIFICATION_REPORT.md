# Этап 1 — качество определения ПД

Дата проверки: 2026-09-23.

## Методика

Проверяется только этап определения ПД, без оценки качества маскирования и производительности.

- Профиль: `autotest`.
- Контекстный ML: включён.
- Детекция: hybrid `ML + rules`.
- 17 обязательных типов ПД из задания.
- Для каждого типа: 5 позитивных и 5 негативных кейсов.
- Всего: 170 заранее зафиксированных кейсов.
- Позитивный кейс считается успешным, если целевой тип присутствует среди итоговых mask-findings.
- Негативный кейс считается успешным, если целевой тип отсутствует.
- Для известных личностей не используется Александр Пушкин. В PERSON-негативах использованы Лев Толстой, Юрий Гагарин, Пётр Чайковский, Дмитрий Менделеев и Антон Чехов.

## Итог

| Показатель | Результат |
|---|---:|
| Все кейсы | 150 / 170 = 88.2% |
| Позитивные кейсы | 77 / 85 = 90.6% |
| Негативные кейсы | 73 / 85 = 85.9% |
| Ошибки всего | 20 |
| Пропуски целевого типа (FN) | 8 |
| Лишние определения целевого типа (FP) | 12 |

На этом независимом стресс-наборе текущая версия не достигает целевого уровня 95% для этапа определения ПД.

## Что работает хорошо

Полностью прошли 10/10: PERSON, BIRTH_DATE, SUBDIVISION_CODE, PASSPORT_ISSUE_DATE, PIN.

Отдельно: PERSON прошёл все 5 негативных кейсов с известными личностями без специального правила под конкретное имя.

## Основные проблемы

1. **CITIZENSHIP — 6/10.** Один пропуск (`Клиентка — гражданка Беларуси`) и три ложных срабатывания на общий/информационный контекст про гражданство.
2. **PASSPORT_ISSUER — 7/10.** Три пропуска валидных формулировок органа выдачи паспорта.
3. **ADDRESS — 8/10.** Ложные срабатывания на адрес встречи и адрес ресторана.
4. **PHONE — 8/10.** Ложные срабатывания на пример номера и номер в роли кода операции.
5. **PAYMENT_CARD — 8/10.** Ложные срабатывания на номер в роли кода операции и тестовый пример карты.
6. Остальные единичные ошибки: PLACE_OF_BIRTH на биографии Юрия Гагарина; CARDHOLDER_NAME на формулировке «имя держателя»; PASSPORT на разделённых серии/номере; DRIVER_LICENSE с ошибочной классификацией как PASSPORT; CVV2; пример EMAIL; INN в роли номера операции.

## Вывод

Текущая hybrid-версия хорошо покрывает базовые позитивные сценарии, но недостаточно уверенно отделяет ПД от неперсонального контекста. Следующий приоритет улучшений — контекстные исключения и разграничение ролей, прежде всего CITIZENSHIP, PASSPORT_ISSUER, ADDRESS, PHONE и PAYMENT_CARD.
