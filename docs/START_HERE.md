# Единая версия для реализации — baseline v1

Дата: 22.09.2026. Это согласованная спецификация, а не отчёт о готовом сервисе.

## Что использовать

- `ARCHITECTURE.md` — решения по API, состоянию, маскированию и безопасности.
- `DETECTION.md` — единые правила 17 типов и границ фрагментов.
- `PII_MATRIX.xlsx` — исправленная классификация и 68 конкретных приёмочных примеров.
- `acceptance_cases.json` — те же примеры с точными offsets для переноса в автоматические тесты.
- `CURSOR_START.md` — готовое первое задание для Cursor.
- `HACKATHON_BRIEF.md` — бриф хакатона / критерии жюри.

Этот комплект заменяет прежние документы как рабочий baseline. Исходные файлы не удалены. При конфликте старых документов с этим комплектом использовать baseline v1. Требования организаторов имеют приоритет над нашим baseline; несовпадение фиксировать, а не молча переписывать API.

## Принятые проектные решения

| Вопрос | Решение v1 |
|---|---|
| Приложение | Python + FastAPI; существующий работающий стек не мигрировать без необходимости |
| Состояние | Redis; атомарная публикация записи и срока жизни |
| Срок хранения | 3600 секунд с момента создания, без продления при retry |
| NER | Локальный адаптер Natasha/Slovnet в приложении; без отдельного HTTP-сервиса в v1 |
| Контекстные типы | Гибрид: NER + локальные правила роли и извлечение явно подписанных полей |
| Адрес | Форматно-контекстный; grammar/parser + контекст |
| Автотест | Все 17 типов включены; именованная политика `autotest_default_v1` |
| Маска для разработки | `dev_redact_v1`: буквы и цифры внутри принятых spans заменяются на `*` |
| Маска для официального прогона | Отдельная стратегия; совместимость пока не подтверждена |
| Proxy | Случайные токены операции, восстановление только после авторизации |
| Не делаем в v1 | Fine-tuning, LLM-fallback, отдельный NER-сервис, UI, response DLP |

## Что исправлено относительно исходных файлов

Адрес одинаково классифицирован во всех файлах. Обнаружение формата отделено от решения маскировать. Устранено ошибочное ожидание, что generic NER обязательно найдёт гражданство или все органы выдачи. Отдельный сервис заменён локальным модулем без изменения логического интерфейса. Конкретизированы offsets, составные реквизиты, пересечения, TTL и ошибки. Архитектурная готовность отделена от готовности работающего продукта.

68 примеров — открытый обучающий/приёмочный набор, не независимый holdout и не доказательство качества. Выполнена проверка структуры примеров, границ spans и локального round-trip по эталонным spans. Сам detector, API, Redis и нагрузка в этом комплекте не реализованы и не протестированы.

## Последовательность работы

| Этап | Где и кто | Действие | Критерий готовности | Возврат в ChatGPT |
|---|---|---|---|---|
| 1. Контракт и состояние | Cursor, Даня | Вставить целиком `CURSOR_START.md` | Автоматические проверки round-trip, retries, conflict, гонки, TTL и отказа Redis | После отчёта Cursor или блокирующей ошибки |
| 2. Detector | Cursor, Соня | Использовать задание этапа 2 в `CURSOR_START.md`; работать после фиксации интерфейса этапа 1 | Отчёт по всем 17 типам и 68 примерам, реальные pass/fail | После отчёта, не после очередного архитектурного предложения |
| 3. Интеграция и proxy | Cursor, Даня | Использовать задание этапа 3 | Все типы включены; mock LLM проверяет отсутствие защищаемых исходных фрагментов; consumer isolation | После тестового отчёта |
| 4. Прогон организаторов | Вручную, Даня | Передать endpoint через официальный канал, запросить правила масок | Получен реальный результат или точный пример ожидаемой маски | С ответом организаторов |
| 5. Качество и нагрузка | Cursor, Даня; вручную, Соня | Задание этапа 5; Соня даёт новый независимый набор | Метрики по типам и размерам, ошибки и ограничения; никакого выдуманного SLA | Перед подготовкой защиты |

Для начала нужен только этап 1. Не передавайте двум агентам одновременное изменение API/state и не запускайте весь backlog одним заданием.

## Только внешние неопределённости

Формат официальных масок и правила их оценки; авторизация/сеть автотестера; допустимый интервал mask→demask; фактический профиль нагрузки. В комплекте есть рабочие defaults, поэтому ответы не блокируют разработку. Утверждать прохождение официальных тестов до прогона нельзя.
