# Проект

Модуль хакатона Alfa-Bank: между системой-потребителем и внешней LLM находит персональные данные, подменяет их и умеет вернуть исходный текст.

AlfaGen в этом репозитории — два разных контура, их нельзя смешивать:

- Платформа проверки. В неё загружают zip исходников (качество кода, score) и отдельно бьют в публичный `POST /process` (маскирование, демаскирование, нагрузка).
- LLM-провайдер для демо. Клиент `app/llm.py` ходит в `ALFAGEN_BASE_URL` моделью `deepseek-ai/DeepSeek-V4-Flash-0731`. Этот вызов не входит в `POST /process`.

Цель текущего дерева: сдать уже собранное решение. Организаторы разрешили не переписывать код через DeepSeek и потребовали указать в README объём сторонних инструментов. Дальнейшую AI-доработку submission-кода ведут в Kilo Code на DeepSeek Flash.

## Ограничения, которые уже зафиксированы

- Контракт автотеста: `POST /process` принимает только `payload` и `payload_id`, отвечает `{result}`.
- В `POST /process` нет вызова LLM и нет обязательного API-ключа.
- В логи, метрики и архив не кладут значения ПД, исходный payload и секреты.
- `.env` не коммитится. Секреты только из окружения.
- Эталон масок организаторов в репозитории нет. Свой набор — `docs/acceptance_cases.json` (68 кейсов). Сравнение с их скрытым датасетом — нормированное span-based расстояние Левенштейна; точная формула порога «95%» в коде не зафиксирована.
