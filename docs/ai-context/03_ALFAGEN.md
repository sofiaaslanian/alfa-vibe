Ниже только то, что видно из репозитория, `.env.example`, `docs/HACKATHON_BRIEF.md` и сообщений организаторов, которые команда зафиксировала. Скрытый датасет не описан.

## Confirmed

- Две проверки обязательны: zip исходников и развёрнутый `POST /process`. Без zip решение не учитывают. Источник: `docs/HACKATHON_BRIEF.md`, раздел про автоматическую проверку; то же в условиях кейса.
- Контракт нагрузки: `POST /process`, JSON `{payload, payload_id}` → `{result}`. Один метод и для маски, и для восстановления. Ключ на этом маршруте не требуется. Код: `app/api.py`.
- Первый запрос с новым `payload_id` маскирует и сохраняет состояние. Второй с тем же id и присланной маской возвращает исходный текст. Код: `app/process.py`, `app/state.py`.
- Нагрузка по приложению B: около 5 минут, цель 1000 RPS, элементы датасета повторяются, таймаут запроса 10 секунд, до 2 ретраев. `429` допустим и не считается невалидным. Пять невалидных ответов подряд останавливают прогон. Источник: `docs/HACKATHON_BRIEF.md`.
- Ориентир задержки автотеста — не больше 1 секунды. Это не жёсткий стоп прогона.
- Качество маски на их прогоне сравнивают с эталоном по нормированному span-based расстоянию Левенштейна. Эталона в репозитории нет.
- В ТЗ указано качество идентификации/маскирования/демаскирования 95%. Как это переводится в расстояние Левенштейна, в коде не зафиксировано.
- Дополнительный плюс ТЗ: 2000 RPS при задержке не больше 1 секунды. Это не условие пятиминутного прогона.
- Крупный текст: до 100 000 токенов. Токенизатор в ТЗ не назван.
- Zip: только исходники, без `.git`, зависимостей, каталогов сборки, датасетов и секретов. Скрипт упаковки: `scripts/pack_submission.sh`.
- LLM демо: OpenAI-совместимый `POST {ALFAGEN_BASE_URL}/chat/completions`, модель по умолчанию `deepseek-ai/DeepSeek-V4-Flash-0731`. Код: `app/llm.py`, `.env.example`.
- Организаторы на вопрос команды ответили: сдавать своё решение; объём сторонних инструментов обязательно указать в README. Это записано в `README.md`.

## Hypotheses / risks

- Их датасет содержит ФИО и адреса в свободном тексте. Текущий `/process` не вызывает NER. Если эталон ждёт спаны, которые находят только модель, расстояние Левенштейна просядет. На внутреннем наборе правила дали 67/68 по `scripts/eval_acceptance.py`; это не их набор.
- Ответ `409` на другой текст с уже известным `payload_id` есть в коде и README. В приложении A этого кода нет. Пять таких ответов подряд остановили бы их прогон. Не проверено, шлёт ли так их система.
- `docker-compose.yml` всё равно поднимает NER и ждёт его healthy, хотя `/process` модель не вызывает. Падение sidecar не даст поднять proxy, даже если автотест мог бы жить на правилах.
- В архиве tracked-файлы `ui/icons.zip` и `ui/photos.zip`. Условие упаковки просит не класть объёмные архивы и медиа. Платформа предыдущий zip приняла, но это риск формальной отбраковки.
- `.env.example` задаёт `PROCESS_CONCURRENCY=180`, Compose по умолчанию подставляет `2`. Поведение стенда зависит от того, какой файл победит.
- README в таблице систем всё ещё пишет, что `autotest` использует RuBERT. `config.yaml` и абзац ниже по файлу говорят обратное: rules-only.
